# 伺服电机控制软件架构设计（阶段性定稿）

> 本文整理当前已讨论并基本确认的伺服电机控制软件架构。<br>
> 目标是先固定**控制语义、模块边界、数据所有权和实时执行关系**，避免为了“架构完整”引入不必要的状态、Target/Ref 层、通用框架或辅助函数。<br>
> 未确认的算法细节统一放在文末“待讨论项”，不作为当前实现约束。

---

## 1. 设计原则

### 1.1 以实际控制语义为核心

软件结构应由真实控制行为决定，不为了形式对称而增加无意义层级。

例如：

- Position / Speed 因为存在轨迹或斜坡生成，需要区分 Target 与 Ref。
- Torque 没有斜坡限制时，不需要为了形式统一再增加一层 Torque Target → Torque Ref。
- Stop、Enable、Disable、Brake 是动作，不应全部设计成持久状态。
- FOC 是控制思想，不设计成一个笼统的 `FOC` 软件模块。

### 1.2 避免过度抽象

当前不倾向：

```c
Motor_Target
Motor_Ref
Motor_Request
Motor_Limited
Motor_Actual
```

这种为了分层而分层的长数据链。

更倾向明确的控制量：

```text
Theta_Ref
Wm_Ref
Iq_Ref
Id_Ref
Ud / Uq
Ualpha / Ubeta
DutyA / DutyB / DutyC
```

每个量有明确的产生者和使用者。

### 1.3 用户负责指令，软件负责安全

核心原则：

> 用户 Command / Target 不因 Limit 被软件偷偷改写。<br>
> 软件只限制当前周期真正能够执行的量，并通过状态告诉用户哪些限制正在生效。

例如：

```text
Torque Command = 30 Nm
当前安全能力只允许 ≈ 20 Nm

用户 Command 保持 30 Nm
实际 Iq_Ref 被限制
Current_Limited = 1
```

当用户指令下降到安全范围后，实际输出正常跟随下降。

---

# 2. Servo、MOS 与动作语义

## 2.1 Servo 与功率级分离

Servo Enable/Disable 是闭环控制状态，不等同于某一个定时器寄存器位，例如：

```c
TIMx->BDTR.MOE
```

实际 MOS 输出状态还受：

- MOE
- CCxP / CCxNP
- OIS
- OSSI / OSSR
- GPIO AF
- Gate Driver Enable
- Timer Break

等硬件配置影响。

因此 Servo 逻辑与 PWM/MOS 底层动作应分开。

---

## 2.2 VBUS 不是 Servo 状态

控制板电源与电机母线可以独立。

MCU 可以在没有 Motor VBUS 的情况下正常启动和运行。

因此：

```text
Bus_Ready
```

是 Enable 的前置条件，而不是一个 Servo State。

---

## 2.3 功率级基本行为

### Active PWM

正常闭环控制：

```text
Complementary PWM
→ FOC Current Control
```

### High-Z

Disable / Coast 时：

```text
High Side OFF
Low Side  OFF
```

即六个 MOS Gate 全部关闭，电机自由滑行。

### Brake

Brake 是独立动作：

```text
High Side OFF
Low Side A ON
Low Side B ON
Low Side C ON
```

三相绕组短接形成电气制动。

Brake 不等于 Disable，也不作为 Fault 的默认动作。

---

# 3. Stop / Disable / Brake

三者必须严格区分。

## 3.1 Stop

Stop 时：

```text
Servo 仍然 Enabled
PWM 仍然工作
闭环继续运行
```

只是根据当前控制模式建立“停止目标”。

### Torque Mode Stop

```text
Iq_Ref → 0
```

当前设计不对 Torque Stop 加斜坡。

### Speed Mode Stop

```text
Speed Target = 0
Speed Ramp 根据 Dec 将 Wm_Ref → 0
```

Servo 保持 Enabled。

### Position Mode Stop

Position Stop 的语义：

> 终止当前运动轨迹，在当前实际位置建立新的静止轨迹并保持。

例如：

```text
原目标      = 100°
实际位置    = 48°
轨迹位置    = 50°
轨迹速度    = 300 rpm
```

Stop 后：

```text
Position Target = 48°
Trajectory Pos  = 48°
Trajectory Vel  = 0
Theta_Ref       = 48°
轨迹阶段清零/复位
```

不能只修改最终 Position Target 而继续运行旧轨迹。

---

## 3.2 Disable

Disable：

```text
Servo退出主动控制
PWM → High-Z
电机自由滑行
```

同时旧的运动命令失去活动语义。

例如：

```text
Speed = 3000 rpm
→ Disable
→ 手动等待
→ Enable
```

重新 Enable 后不能恢复 3000 rpm。

---

## 3.3 Brake

Brake 是独立命令：

```text
正常闭环控制停止参与
High Side OFF
3 × Low Side ON
```

只有明确需要 Brake 时才调用。

Fault 不默认进入 Brake。

---

# 4. Enable 行为

Enable 不是运动命令。

核心原则：

> Enable 时不能恢复历史运动，而应该根据当前模式建立安全的静止参考状态。

---

## 4.1 Torque Mode Enable

```text
Iq_Ref = 0
```

---

## 4.2 Speed Mode Enable

```text
Speed Target = 0
Wm_Ref       = 0
Speed Ramp State Reset
```

不能把旧的速度 Ref 再慢慢降下来。

---

## 4.3 Position Mode Enable

Enable 前尽可能接近实际开始主动控制的时刻采集当前位置：

```text
Position Target = Theta_Actual
Trajectory Pos  = Theta_Actual
Trajectory Vel  = 0
Theta_Ref       = Theta_Actual
Trajectory State Reset
```

例如：

```text
Disable前位置 = 100°
Disable期间被外力移动到150°
Enable Position Mode
```

结果：

```text
保持150°
```

而不是回到100°或零点。

---

# 5. 控制模式切换

控制模式：

```text
Torque
Speed
Position
```

模式只允许在：

```text
Servo Disabled
```

时切换。

Enabled 状态执行：

```text
SetMode(...)
```

直接返回：

```text
CMD_INVALID_STATE
```

不：

- 自动 Disable
- 自动切换
- 自动重新 Enable
- 生成 Warning/Fault

当前只需要一个：

```text
Ctrl_Mode
```

不需要：

```text
Requested_Mode
Pending_Mode
Active_Mode
```

`SetMode()` 只负责修改模式。

Position 模式的位置同步应放在 Enable，而不是 SetMode，因为 SetMode 后电机还可能在 Disabled 状态被外部移动。

---

# 6. Command / Target / Ref

## 6.1 Position Mode

Position 命令：

```text
Target Position
Vel_Max
Acc
Dec
```

数据流：

```text
Position Command
      ↓
T Profile / Motion
      ↓
Theta_Ref
      ↓
Position Loop
```

---

## 6.2 Speed Mode

Speed 命令：

```text
Target Speed
Acc
Dec
```

数据流：

```text
Speed Command
      ↓
Speed Ramp
      ↓
Wm_Ref
      ↓
Speed Loop
```

Speed Ramp 与 Speed Loop 同步执行。

---

## 6.3 Torque Mode

用户接口保持物理意义：

```text
Torque Command [Nm]
```

进入内部控制前通过电机 `Kt` 参数转换：

```text
Torque Command
      ↓
Torque → Current Mapping
      ↓
Iq_Ref
```

简单 PMSM 第一版：

```text
Iq ≈ Torque / Kt
```

因此核心控制链中不再需要长期保留 `Te_Ref`。

---

# 7. 主控制级联关系

## 7.1 Torque Mode

```text
Torque Command [Nm]
      ↓
Kt / Torque-Current Mapping
      ↓
Iq_Ref
      ↓
Current Loop
```

---

## 7.2 Speed Mode

```text
Speed Target
      ↓
Speed Ramp
      ↓
Wm_Ref
      ↓
Speed Loop
      ↓
Iq_Ref
      ↓
Current Loop
```

Speed Loop 的输出单位直接为：

```text
A
```

即输出 `Iq_Ref`。

---

## 7.3 Position Mode

```text
Position Target
      ↓
T Profile
      ↓
Theta_Ref
      ↓
Position Loop
      ↓
Wm_Ref
      ↓
Speed Loop
      ↓
Iq_Ref
      ↓
Current Loop
```

T Profile 可以内部具有：

```text
Trajectory Position
Trajectory Velocity
Trajectory Phase
```

但 `Trajectory Velocity` 不等同于 Speed Loop 的 `Wm_Ref`。

未来如果增加速度前馈，再单独讨论。

---

# 8. Ref 所有权

当前控制链应尽量保持单一写入者。

| Ref / Output | 主要产生者 |
|---|---|
| `Theta_Ref` | T Profile / Position Stop / Position Enable |
| `Wm_Ref` | Speed Ramp 或 Position Loop |
| `Iq_Ref` | Torque Mapping 或 Speed Loop |
| `Id_Ref` | Current Strategy |
| `Ud/Uq` | Current PI / Current Control |
| `Ualpha/Ubeta` | Current Loop |
| `DutyA/B/C` | SVPWM |

Limit 不作为第二个 Ref Owner。

Limit 应作为产生 Ref 或控制输出过程中的约束。

---

# 9. Limit 架构

Limit 不属于 Fault 严重等级。

Limit 由两个部分组成：

```text
1. 分布在控制计算中的实际限幅
2. Limit Status 汇总 / 回参 / 监测
```

---

## 9.1 分布式执行限幅

不同限制放在真实算法的位置。

例如：

```text
Speed Loop Output
      ↓
Iq Output Saturation
      ↓
Iq_Ref
```

```text
Current Loop Input
      ↓
dq Current Reference Limit
```

```text
Current PI Output
      ↓
dq Voltage Vector Limit
```

```text
SVPWM Output
      ↓
Duty Feasibility Limit
```

---

## 9.2 Limit Status

Limiter 可以产生运行状态：

```text
Current_Limited
Voltage_Limited
Torque_Limited
Speed_Limited
Positive_Position_Limited
Negative_Position_Limited
```

这些状态用于：

- 上位机回参
- 调试
- Anti-Windup
- Protection Monitor 判断

但 Limit Status 本身不是 Warning/Fault。

---

## 9.3 Limit 不修改用户 Target

例如：

```text
Position Target = 10 rad
Positive Soft Limit = 8 rad
Actual Position = 8 rad
```

软件不做：

```text
Position Target = 8 rad
```

而是：

```text
继续正向运动 → 限制
反向退出     → 允许
```

即：

> 危险方向锁住，安全退出方向允许。

---

# 10. Command Error / Notice / Warning / Fault

三类概念分离：

```text
Command Result
Device Health
Control Limit
```

---

## 10.1 Command Result

表示命令是否正确执行。

例如：

```text
Enabled状态 SetMode
→ CMD_INVALID_STATE
```

不进入 Warning/Fault。

---

## 10.2 Device Health

异常严重度：

```text
Notice
Warning
Fault
```

### Notice

提示状态，不影响运行。

### Warning

设备进入需要关注区域：

```text
Servo继续运行
不修改用户Target
```

### Fault

继续运行不安全：

```text
Force Disable
PWM → High-Z
```

Fault 消失后不自动重新 Enable。

必须：

```text
Fault条件恢复
→ ClearFault
→ Servo仍Disabled
→ 用户重新Enable
```

---

## 10.3 Limit 与 Warning 的关系

达到正常控制限制不一定是 Warning。

例如正常加速：

```text
Speed PI要求 30A
Iq_Max = 20A
Iq_Ref = 20A
Current_Limited = 1
```

这是正常控制行为。

如果产品定义：

```text
持续限流3秒
```

需要提示用户，则由监测逻辑进一步产生 Warning。

因此：

> Limit Status 是事实；Warning 是对状态严重程度的判断。

---

# 11. 硬件快速 Fault

对于硬件比较器、Gate Driver 等快速保护：

```text
Comparator / Driver Fault
      ↓
Timer Break / BKIN
      ↓
PWM Hardware Shutdown
      ↓
Software记录 Fault
```

不能等待软件检测后再关 PWM。

硬件过流后也不能自动切换成三下管 Brake。

默认安全动作：

```text
PWM → High-Z
```

---

# 12. 控制周期与调度

当前设计：

```text
PWM Frequency       = 20 kHz
Current Loop        = 20 kHz
Speed Observer      = 20 kHz
Speed Loop          = 2 kHz
Speed Ramp          = 2 kHz
Position Loop       = 1 kHz
```

未来可能：

```text
PWM = 20 kHz
Current Loop = 40 kHz
```

通过每 PWM 周期双采样双更新实现。

---

## 12.1 Fast Tick

Fast Tick 由 ADC Conversion Complete 驱动。

推荐：

```text
PWM Hardware Trigger
      ↓
ADC Sample
      ↓
ADC Complete IRQ
      ↓
Fast Control Tick
```

外环通过整数分频运行。

同一个 Fast Tick 同时触发多个环时，顺序：

```text
State / Angle Processing
      ↓
Position Loop
      ↓
Speed Loop
      ↓
Current Loop
```

这样新的 `Wm_Ref` / `Iq_Ref` 可以在同一次控制 Tick 向下传播。

---

# 13. Current Loop 定义

当前确认的定义：

> **Current Loop 负责把“想要的 dq 电流”变成“当前硬件实际允许的 αβ 电压矢量”。**

---

## 13.1 Current Loop 输入

```text
Id_Ref
Iq_Ref

Ia / Ib / Ic
FOC_Angle
Vbus / Voltage Base相关信息
```

---

## 13.2 Current Loop 内部

```text
Id_Ref / Iq_Ref
      ↓
dq Current Ref Final Limit
      ↓

Ia / Ib / Ic
      ↓
Clarke
      ↓
Ialpha / Ibeta
      ↓
Park ← FOC_Angle
      ↓
Id / Iq
      ↓
Id / Iq PI
      ↓
Ud_req / Uq_req
      ↓
dq Voltage Vector Limit
      ↓
Ud / Uq
      ↓
InvPark
      ↓
Ualpha / Ubeta
```

---

## 13.3 Current Loop 输出

```text
Ualpha
Ubeta
```

SVPWM 不属于 Current Loop。

---

## 13.4 Current Ref 最终限制

Speed Loop 自己的 PI 输出需要饱和，用于控制算法与 Anti-Windup。

同时 Current Loop 输入侧仍保留最终安全电流限制。

因此：

```text
Speed PI
   ↓
Output Saturation
   ↓
Iq_Ref
   ↓
Current Loop
   ↓
Final dq Current Ref Limit
```

两级限制职责不同：

- Speed Loop Saturation：控制器自身输出范围。
- Current Loop Limit：最终电流安全边界。

Torque Mode 没有 Speed Loop，因此最终 Current Loop Limit 必须存在。

---

# 14. 电压限幅

电压限幅位于：

```text
Current PI最终电压请求
      ↓
Voltage Vector Limit
      ↓
InvPark
```

如果以后增加：

```text
Current PI
Decoupling
Back-EMF Feedforward
```

应先合成为最终：

```text
Ud_req
Uq_req
```

然后统一做 Voltage Limit。

---

## 14.1 dq 矢量限幅

应限制整个 dq 电压矢量。

例如标幺系统：

```text
|Udq| <= 0.9 pu
```

正常情况下限制后：

```text
InvPark
→ Ualpha/Ubeta
```

已经属于可调制的合法电压矢量。

---

# 15. 标幺值

控制环路尽量使用标幺值。

例如：

```text
Id / Iq        pu
Ud / Uq        pu
Ualpha/Ubeta   pu
```

Current PI 输出电压限制可设计为：

```text
0.9 pu
```

保留一定调制余量。

但当前还有一个必须后续正式统一的定义：

> `1.0 pu Voltage` 到底代表什么。

推荐方向：

```text
1.0 pu
=
SVPWM线性调制区能够实现的最大电压矢量
```

这样：

```text
0.9 pu
```

就是明确的 10% 调制余量。

此定义仍需结合最终 SVPWM 标幺公式确认。

---

# 16. SVPWM 模块

SVPWM 与 Current Loop 分离。

输入：

```text
Ualpha
Ubeta
```

以及必要的标幺 / Vbus 信息。

输出：

```text
DutyA
DutyB
DutyC
```

SVPWM 不负责：

- Current PI
- Iq_Ref 修改
- 控制模式
- Servo 状态

---

## 16.1 Duty 最终限值

即使 Current Loop 已经保证：

```text
|U| <= 0.9 pu
```

SVPWM 最后仍应该做 Duty 输出合法性保护。

概念上：

```text
DutyA/B/C ∈ [0, 1]
```

或根据实际硬件：

```text
Duty_Min <= Duty <= Duty_Max
```

该限制主要用于：

- 浮点边界误差
- 最小脉宽
- Dead Time
- Driver 可实现条件
- ADC 有效采样窗口
- PWM Hardware Feasibility

正常控制中不应长期依赖 Duty Clamp 来实现电压限幅。

---

# 17. PWM / MOS 底层职责

PWM Hardware 负责：

```text
DutyA/B/C
      ↓
Timer Compare / Preload
      ↓
Complementary PWM
      ↓
Gate Driver
```

以及明确的底层动作：

```text
PWM Active
PWM High-Z
PWM Brake
```

不把控制算法放入 PWM 层。

---

# 18. 电流采样

当前硬件：

```text
Three Low-Side Shunts
```

即三相下管采样电阻。

电流采样时刻由 PWM 配置决定。

中心对齐 PWM 下，候选采样参考点：

```text
ARR 顶点
CNT = 0
```

双采样时两个位置都可作为采样事件，但必须结合实际：

- PWM 极性
- Complementary 配置
- Dead Time
- Duty
- MOS 开关状态
- 下管有效采样窗口

确认是否有效。

因此架构中定义：

```text
PWM Sample Event A
PWM Sample Event B
```

而不把算法写死为 ARR / CNT=0。

---

## 18.1 ADC Trigger

ADC 必须由 PWM Timer 硬件事件触发。

推荐：

```text
PWM Timer Event
      ↓
ADC Injected Trigger
      ↓
ADC Conversion
      ↓
ADC EOC IRQ
      ↓
Fast Control Tick
```

不要：

```text
Timer IRQ
→ Software Start ADC
```

这样 CPU 中断延迟不会改变真实电流采样时刻。

---

## 18.2 Sample Offset

实际 ADC Trigger 不一定正好位于 ARR 或 CNT=0。

可以设置：

```text
PWM Sample Reference
      +
Sample Offset
      ↓
ADC Trigger
```

用于避开：

- MOS switching transient
- Dead Time
- Gate propagation
- Current Amp settling
- PCB ringing

参考工程使用过：

```text
下溢后 600 ns
```

但当前项目具体值需要根据硬件实测决定。

---

# 19. ADC 与 Encoder 快环同步方案

核心原则：

> ADC 和 Encoder 不要求“通信完成时刻相同”，而要求最终用于 Current Loop 的电流和角度都对应同一个物理采样时刻。

---

## 19.1 PWM 是统一时间基准

定义：

```text
Current Sample Event
Encoder Acquisition Event
```

编码器采集事件可以放在目标电流采样点之前约半个 PWM 周期。

例如单采样 20 kHz：

```text
PWM另一顶点
      ↓
启动Encoder读取
      ↓
Raw Angle Ready
      ↓
下一Current Sample Event
      ↓
ADC采样
      ↓
ADC EOC
      ↓
Fast Control Tick
```

---

## 19.2 Encoder 不阻塞 Current Loop

禁止：

```text
ADC IRQ
→ Start Encoder Read
→ Wait Encoder
→ Current Loop
```

正确方式：

```text
PWM Event
→ 提前启动Encoder采集
→ DMA/IRQ得到Raw Angle
→ 只更新Encoder原始数据

之后：

ADC EOC
→ Fast Tick
→ 使用已经准备好的Encoder数据
```

---

## 19.3 Encoder Raw 与 Control State 分离

Encoder DMA / USART / SPI 中断只负责：

```text
Raw Position
New_Data
Valid
```

不要在通信中断里直接运行：

```text
Position Loop
Speed Loop
Current Loop
```

真正控制状态更新锁定在 Fast Tick。

---

# 20. Encoder 时间对齐

如果编码器实际测量时间：

```text
t_enc
```

电流 ADC Sample 时间：

```text
t_sample
```

Current Loop 需要：

```text
ThetaE(t_sample)
```

而不是简单使用最近收到的 Raw Angle。

基本补偿关系：

```text
ThetaM(t_sample)
≈ ThetaM(t_enc)
+ Wm × (t_sample - t_enc)
```

再计算：

```text
ThetaE(t_sample)
=
PolePairs × ThetaM(t_sample)
+ ElectricalOffset
```

因此：

```text
Park:
Iabc(t_sample)
+
ThetaE(t_sample)
```

二者对应同一物理时刻。

---

## 20.1 ADC EOC 不是电流真实采样时刻

必须区分：

```text
ADC Trigger
      ↓
Sample & Hold     ← 电流真正对应的时间
      ↓
ADC Conversion
      ↓
ADC EOC           ← CPU拿到结果的时间
```

做角度补偿时应该用：

```text
t_current_sample - t_encoder_measurement
```

而不是：

```text
ADC_ISR_Time - Encoder_IRQ_Time
```

---

# 21. Park 与 InvPark 的角度时刻

严格来说存在两个不同时间：

### Park

处理的是已经采样的电流：

```text
Iabc(t_sample)
```

因此应使用：

```text
ThetaE_Sample = ThetaE(t_sample)
```

### InvPark

Current Loop 算出的电压真正施加到电机存在控制延迟：

```text
ADC Conversion
+ ISR Latency
+ Current Calculation
+ SVPWM
+ PWM Buffer / Latch
```

因此未来高速优化时可以使用：

```text
ThetaE_Apply
≈ ThetaE_Sample + We × T_delay
```

第一版可以：

```text
ThetaE_Apply = ThetaE_Sample
```

但架构上保留以后加入固定延迟补偿的可能。

```text

```

例如：

```text

→ Current Loop A
```


# 23. Encoder / Position 基础数据

当前编码器常见：

- SPI
- RS-485
- 单圈硬件绝对值编码器

内部角度统一使用：

```text
rad
```

内部速度统一使用：

```text
rad/s
```

建议概念状态：

```text
ThetaM_Raw
ThetaM
ThetaM_Est

Wm_Raw
Wm_Est

ThetaE / FOC_Angle
```

其中：

- `ThetaM_Raw`：单圈机械角。
- `ThetaM`：软件 unwrap 后的连续机械位置。
- `Wm_Raw`：简单差分速度，便于开发调试。
- `Wm_Est`：Observer 输出，正式 Speed Loop Feedback。
- `FOC_Angle`：经过 Encoder / Position Processing 后提供给 Current Loop。

# 29. 代码风格倾向

当前架构对应的代码风格：

- 偏 Simulink / 控制框图式数据流。
- 模块输入 → 算法 → 限幅 → 输出。
- 不依赖外围函数事后修改内部状态。
- 避免纯软件工程式超长命名。
- 避免无必要 Init 层级和状态机。
- 算法简单时允许直接明确表达。
- 不为了“所有模式统一”建立巨大通用结构体。
- 不为了“所有动作统一”把 Action 全部变成 State。
- Ref 尽量单一 Writer。
- Hardware Driver 只处理硬件语义，不吞入控制策略。

例如倾向：

```c
Current_Loop();
Speed_Loop();
Position_Loop();

Clarke();
Park();
InvPark();

SVPWM_Calc();
Current_Reconstruct();
```

而不是：

```c
FOC_System_Main_Control_Manager_Run();
Servo_Control_Reference_Management_Update();
```
