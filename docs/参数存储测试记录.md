## 当前 NVS 接口（2026-10-19）

```c
int NVS_Storage_Load_All(void);
int NVS_Storage_Save_All(void);
int NVS_Storage_Save_Ids(const uint16_t *Ids, uint16_t Count);
```

- `Load_All`：启动时读取各持久化 Parameter，统一通过 `Parameter_Restore()` 校验并写入 RAM；缺失、长度错误或数值非法的记录保留原值。电机模型、ESO 带宽、标定方向、偏置和有效标志都按表逐项恢复。该接口不计算控制系数，也不配置编码器。
- `Save_All`：按参数表保存全部持久化 Parameter，包括独立存放在 `Current_Manual` 和 `Speed_Manual` 的 Kp/Ki；Bandwidth 模式计算出的 Effective Kp/Ki 不存储。保存失败返回错误，由调用方决定是否重试，不自动恢复旧值。
- `Save_Ids`：一次遍历，按输入顺序逐项检查 ID、读取并保存；遇到非法 ID 或写入失败立即返回，已保存的参数不恢复。当前寻相保存 RAM 中的方向、偏置和有效标志三项参数，不提前写入 `Valid=0`。该操作不是整组原子保存。

现不再提供按 ID 单独 Load、排除列表 Save 或 `NVS_ALL` 哨兵。切换 Bandwidth/Manual 只修改 RAM 运行增益来源，不访问 Flash。

## 1. Manual 增益保留与 NVS 选择保存回归（2026-10-07，主机测试）

本次解决 Bandwidth 下保存配置会覆盖已有手调增益、切回 Manual 无法恢复的问题。
不调整电流/速度/位置控制器数值，不改变参数 ID、Flash 记录格式或控制周期。
本轮没有重新烧录、操作电机或改写开发板 NVS；以下是主机回归和固件构建结果。

### 公共存储 API 与调用方策略

```c
int NVS_Storage_Save(const uint16_t *Ids, uint16_t Count, NVS_Select_e Select);
int NVS_Storage_Load(uint16_t Id);
```

| 调用 | 行为 |
|---|---|
| `Save(Ids, Count, NVS_INCLUDE)` | 按列表顺序保存指定持久化参数 |
| `Save(Ids, Count, NVS_EXCLUDE)` | 保存除列表所列 ID 之外的持久化参数 |
| `Save(NULL, 0, NVS_INCLUDE)` | 不保存任何参数 |
| `Save(NULL, 0, NVS_EXCLUDE)` | 保存全部持久化参数，包括当前运行增益 |
| `Load(Id)` | 读取指定 Flash 记录，经 `Parameter_Restore()` 校验后写入 RAM，不触发修改回调 |
| `Load(NVS_ALL)` | 全量恢复；缺失/非法记录保留 RAM 原值，之后统一更新模型、编码器和校准有效性 |

列表中含未知或非持久化 ID、非空数量配空指针、非法选择方式，保存返回错误；
列表校验在写入前完成。重复 ID 可以传入，底层 NVS 对相同记录返回 0 时仍算成功。
多项保存不是掉电事务；发生写错误时停止，之前已成功的记录仍保留。

`NVS_Storage_Save()` 不检查 Bandwidth/Manual。`MOTOR_CMD_PARAMETER_SAVE` 的处理处
根据两个环各自的来源生成最多六个排除 ID：电流环 Bandwidth 排除 Id/Iq 四个增益，
速度环 Bandwidth 排除速度 Kp/Ki。配置保存仍只允许 DISABLED。
直接调用公共保存 API 可以保存带宽计算出来的增益，这是公共接口的明确语义。

校准保存使用 INCLUDE 列表，保留原有顺序：先保存 `Valid=0`，然后保存极对数、
编码器配置、方向和偏置，最后保存 `Valid=1`。任一步失败立即返回，不继续写后续记录。

### Manual 切换

显式从 Bandwidth 切到 Manual 时，参数层按 ID 调用公共加载接口恢复对应增益。
重复写入 Manual 不重新加载，保留未保存的 RAM 调参结果；修改增益仍沿用原来的
隐式 Manual 行为，写入相同值不触发回调的原有规则也保留。

整组 Flash 记录均不存在时，沿用当前增益作为首次手调起点；部分缺失、长度错误、
非法数值或读取失败时，撤销本次已经恢复的增益并返回配置错误，来源保持 Bandwidth。
回退只使用本次调用的局部旧值，不增加常驻手调副本。
单项加载与回退逐项执行，不提供跨中断的整组原子切换，也不在 Flash 读取期间关中断。
来源切换继续只允许 DISABLED/ENABLED，RUN 拒绝修改。

上电全量加载保持原有规则：Bandwidth 根据恢复后的带宽和模型计算 PI，Manual 保留
Flash 中恢复的 PI。旧固件若已经用计算值覆盖了手调值，新固件无法找回历史值，需重新
手调并执行一次保存配置。

## 2. Manual 配置与 Effective 增益分离、ESO 提交校验（2026-10-07，主机测试）

测试对象：`feat/torque-ramp-adc-timing`，基于 `7fcf228` 的本次工作区修改。
本轮未烧录、未操作电机、未改写开发板 NVS；Save/reboot 用内存 NVS 和重新初始化 RAM 验证，不代表 Flash 掉电可靠性或实机验收。

### 参数与切换语义

| 数据 | 保存位置与作用 |
|---|---|
| `Current_Manual` 的 Id/Iq Kp/Ki、`Speed_Manual` 的 Kp/Ki | 独立 RAM 配置；原六个 Gain ID 改绑至此，仍持久化 |
| Current/Speed Bandwidth、Source | 保留原 ID，仍持久化 |
| `Id_Ctrl.Para`、`Iq_Ctrl.Para`、`Speed_Ctrl.Para` 的 Kp/Ki | 当前实际运行增益；由对应 `Tuning_Update()` 发布，不持久化 |
| `0x0A14` / `0x0A15` | 新增只读 Speed Effective Kp/Ki，不持久化；速度测试脚本改读这两个参数 |

写 Manual Gain 自动选择 Manual 并发布整组手调配置；写 Bandwidth 自动选择 Bandwidth 并计算运行增益。
即使写入值与 RAM 相同，也执行来源选择。显式切 Source 只按新来源发布增益，不读取 Flash。
例如已保存 Kp=0.04，再在 RAM 改为 0.05，切 Bandwidth 后切回 Manual，仍为 0.05；只有重新上电加载才恢复已保存配置。

Save 命令仍要求 DISABLED，直接保存全部持久化配置，删除 `Skip[6]` 来源过滤。
Bandwidth 模式下也保存 Manual RAM，不会把派生 Effective 值写入原 Gain 记录。
Current/Speed 的 Source、Gain、Bandwidth 仍为 NOT_RUNNING 权限，RUN 下拒绝写入。

97 个既有参数/动作的顺序、ID 和类型逐项核对保持不变；只在字典末尾追加两个只读参数。
旧 NVS Gain 记录直接解释为 Manual 配置，缺失则保留默认 Manual 值。旧固件已经覆盖掉的手调值无法追溯恢复。
Host 原 Gain 字段现在显示 Manual 配置；需要实际速度增益的显示或记录应使用新 Effective ID。

### ESO 与模型发布

`Mechanical_ESO_Para_Build()` 只计算局部候选系数，检查物理输入及各系数有限性、L1/L2 正值；失败不改变输出。
`Motor_Para_Update(候选模型, 候选 ESO 带宽)` 先计算和检查，成功后在短临界区发布模型、带宽与 ESO 系数，保持 ESO State。
失败时模型参数、ESO 带宽、系数和 State 都保持旧值，不执行先写入再回滚，也不清零 ESO。
极对数变化引起的校准失效只在候选通过后执行。

Parameter 写模型/ESO 带宽走该候选路径，失败返回参数值错误。辨识 Apply 也走相同路径，避免直接写入无效 J/B 或 Flux。
Rs/Ls 粗探测仍临时替换电气模型并使用 Bandwidth，结束后恢复原模型和 Source，由来源重新生成增益；Manual 配置不参与临时备份或覆盖。

NVS 全量读取先收集完整模型与 ESO 带宽，再统一校验、发布，避免新 J 配旧 B 等中间组合导致错误拒绝。
缺失或标量非法记录保持 RAM 原值；完整候选仍非法时返回 `-EINVAL`，保留旧模型和 ESO，其他独立配置照常恢复，不接受该组存储校准，也不执行会清零 ESO State 的编码器硬件重配。
全量加载成功后仍沿用原有编码器重配流程，其反馈状态重置与 ESO 候选系数发布是不同动作。
上电首次配置被拒绝时 ESO 保持无效，有感使能沿用已有有效性检查。
单项模型/ESO 加载也先校验；普通单项加载仍只恢复配置、不触发来源选择回调。

删除 Parameter 对 NVS 的依赖、Manual 切换 Load/Missing/rollback、来源变化的无语义包装，以及无真实调用点的 `Current_Loop_Track()`。
未更改控制周期、电流环公式、速度/位置控制算法或轨迹算法。
