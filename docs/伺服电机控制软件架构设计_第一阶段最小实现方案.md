# 伺服电机控制软件架构设计——第一阶段最小实现方案

> 本文基于《伺服电机控制软件架构设计（阶段性定稿）》进一步收缩当前实现范围。<br>
> 当前目标不是一次性实现完整伺服功能，而是优先让 **AXDR_L 开发板 + 2312S SPI 编码器电机** 完成基本闭环运动：
>
> **电流环 → 转速环 → 位置环**
>
> 在三环稳定运行以后，再逐步加入 ESO、IPD、寻相、参数辨识、动态 ADC 采样等功能。
>
> 当前工程基础：
>
> - AXDR_L 开发板硬件已可使用。
> - 2312S 电机，带 SPI 编码器。
> - STM32CubeMX 基础 `.ioc` 已基本配置。
> - RTOS 使用 Eclipse ThreadX。
> - USB 基础功能已配置。
>
> 本阶段核心原则：
>
> > **代码逻辑尽量直接、简短。只实现当前闭环运行真正需要的功能，不提前为未来功能增加复杂状态、管理层和动态策略。**

# 2. Servo 状态

第一阶段 Servo 只保留三个状态：

```c
typedef enum
{
    SERVO_DISABLED = 0,
    SERVO_ENABLED,
    SERVO_RUN,
} Servo_State_e;
```

控制模式保持独立：

```c
typedef enum
{
    CTRL_TORQUE = 0,
    CTRL_SPEED,
    CTRL_POSITION,
} Ctrl_Mode_e;
```

因此：

```text
Servo_State
    ├─ DISABLED
    ├─ ENABLED
    └─ RUN

Ctrl_Mode
    ├─ TORQUE
    ├─ SPEED
    └─ POSITION
```

`RUN` 是 Servo 的运行状态，不是新的控制模式。

---

# 3. Servo 状态转换

```text
             Enable
 Disabled ─────────────→ Enabled
                            │
                            │ Run
                            ▼
                           Run
                            │
                            │ Stop
                            ▼
                         Enabled

Enabled / Run
     │
     │ Disable / Fault
     ▼
 Disabled
```

不增加：

```text
READY
IDLE
STOPPING
DECELERATING
PENDING
ACTIVE
```

等额外状态。

---

# 4. Target 与 Run 权限

本阶段采用一个明确规则：

> **Target 表示用户要求，不因 Enable / Disable 自动清除。**

例如：

```text
Speed_Target = 100 rad/s
Servo_State  = DISABLED
```

是合法状态。

此时：

```text
目标已经保存
但没有运动执行权
```

只有：

```text
Servo_State == SERVO_RUN
```

时，Target 才允许进入实际运动控制链。

因此不需要：

```text
Pending_Target
Requested_Target
Active_Target
```

等多层目标。

只保留：

```text
Torque_Command
Speed_Target
Position_Target
```

---

# 5. DISABLED

`SERVO_DISABLED`：

```text
PWM → High-Z
电机不主动输出驱动力
控制目标可以修改
控制目标不执行
```

Disable 后：

```text
Servo_State → DISABLED
PWM         → High-Z
```

用户已经设置的：

```text
Torque_Command
Speed_Target
Position_Target
```

可以继续保存。

但重新 Enable 后不会自动运动。

---

# 6. ENABLED

`SERVO_ENABLED` 表示：

> 功率级和闭环已经建立，但尚未开始执行用户运动目标。

因此：

```text
Enable != Run
```

Enable 时不修改用户 Target。

---

## 6.1 Torque Mode Enable

```text
Iq_Ref = 0
```

即使：

```text
Torque_Command != 0
```

也暂时不执行。

---

## 6.2 Speed Mode Enable

```text
Wm_Ref = 0
Speed Ramp State → 静止状态
```

但：

```text
Speed_Target
```

保持不变。

例如：

```text
Speed_Target = 100 rad/s
Enable
```

结果：

```text
Speed_Target = 100 rad/s
Wm_Ref       = 0
Servo_State  = ENABLED
```

电机不运行。

---

## 6.3 Position Mode Enable

Enable 时读取当前实际机械位置：

```text
Theta_Ref = Theta_Actual
```

必要的 Position Loop / Motion 内部状态同步到当前位置。

但：

```text
Position_Target
```

保持原值。

例如：

```text
当前位置        = 1.2 rad
Position_Target = 5.0 rad
```

执行：

```text
Enable
```

结果：

```text
Theta_Ref       = 1.2 rad
Position_Target = 5.0 rad
Servo_State     = ENABLED
```

此时电机保持当前位置，不执行 5.0 rad 目标。

---

# 7. RUN

执行：

```c
Servo_Run();
```

之后：

```text
Servo_State = SERVO_RUN
```

此时当前控制模式下保存的 Target 才真正开始执行。

```text
      ↓

```

## 7.2 Speed Mode

```text

      ↓
Speed Ramp
      ↓
Wm_Ref
      ↓
Speed Loop
      ↓
Iq_Ref
      ↓
```

---

## 7.3 Position Mode

```text
当前位置
   ↓
建立本次位置运动
   ↓
Position_Target
   ↓
Theta_Ref
   ↓
Position Loop
   ↓
Wm_Ref

```

例如：

```text

```

执行：

```text

```

才真正开始：

```text

```

# 8. Stop

Stop 与 Disable 分开。

Stop 后：

```text
Servo_State → SERVO_ENABLED
```

Servo 仍然保持主动闭环。

---

## 8.1 Torque Stop

Torque Stop：

```text
实际执行转矩 → 0
Iq_Ref       → 0
Servo_State  → ENABLED
```

本阶段实现可以直接停止，不增加 Torque Ramp。

---

## 8.2 Speed Stop

Speed Stop：

```text
运行目标 → 0
Speed Ramp 按 Dec 降到 0
Servo_State → ENABLED
```

Speed Loop 继续工作，使电机主动减速并保持零速。

不增加：

```text
STOPPING
```

独立状态。

---

## 8.3 Position Stop

Position Stop：

```text
终止当前运动
当前位置作为新的静止位置
Theta_Ref = Theta_Actual
Servo_State = ENABLED
```

位置环继续保持当前位置。

---

# 9. SetMode

控制模式：

```text
Torque
Speed
Position
```

第一阶段仍采用：

> **只允许在 SERVO_DISABLED 状态切换模式。**

因此：

```text
DISABLED → SetMode() 允许
ENABLED  → SetMode() 拒绝
RUN      → SetMode() 拒绝
```

不自动：

```text
Disable
切换模式
重新 Enable
```

# 10. 第一阶段 ADC 方案

第一阶段 ADC 不实现动态两相选择。

核心目标：

> **固定采样方案，把电流环先稳定跑通。**

固定：

```text
PWM Sample Event
      ↓
ADC Hardware Trigger
      ↓
固定 ADC Channel
      ↓
Current Sample
```

如果当前硬件采用两相采样：

```text
Ia = ADC_Ia
Ib = ADC_Ib
Ic = -(Ia + Ib)
```

如果三相 ADC 都已经方便读取，也可以固定：

```text
Ia = ADC_Ia
Ib = ADC_Ib
Ic = ADC_Ic
```

第一阶段选择当前硬件上代码最简单、最稳定的方案。

---

## 10.1 暂不实现的 ADC 功能

第一阶段不实现：

```text
Sector 判断
最大 Duty 相判断
动态选择两相
动态 ADC Channel 切换
采样窗口有效性判断
Invalid Sample
第二大 Duty 判断
双采样
40 kHz 双更新
```

也不为了极高占空比提前复杂化 Current Sample 模块。

以后如果固定采样真正限制了工作范围，再单独升级：

```text
Current_Sample()
```

上层 Position / Speed / Current 控制链不改变。

# 11. ADC 触发方式

ADC 仍然坚持由 PWM Timer 硬件触发。

```text
PWM Timer
    ↓
Hardware ADC Trigger
    ↓
ADC Sample
    ↓
ADC EOC
    ↓
Fast Control Tick
```

不使用：

```text
Timer IRQ
    ↓
Software Start ADC
```

避免 CPU 中断延迟改变实际采样时刻。

# 12. Encoder 第一阶段方案

2312S 使用 SPI 编码器。

第一阶段只完成：

```text
SPI Raw Position
      ↓
Mechanical Angle
      ↓
Angle Unwrap
      ↓
Electrical Angle
```

主要输出：

```text
ThetaM
ThetaE
```

其中：

```text
ThetaE
=
PolePairs × ThetaM
+ ElectricalOffset
```

第一阶段允许：

```text
ElectricalOffset
```

由手动测试或已有方法获得并作为参数写入。

暂时不要求自动寻相。

---

# 13. 第一阶段 Speed Feedback

第一阶段不使用 ESO。

速度先通过编码器位置差分得到：

```text
ThetaM(k)
    ↓
Difference
    ↓
Raw Speed
    ↓
Simple LPF
    ↓
Wm
```

即：

```text
Position Loop Feedback = ThetaM
Speed Loop Feedback    = Wm
FOC Angle              = ThetaE
```

目标是减少首次闭环调试中的变量数量。

后续再把：

```text
Difference + LPF
```

替换或扩展为：

```text
ESO
```

> **把期望 dq 电流变成当前可执行的 αβ 电压矢量。**

```text

      ↓
Current Limit
      ↓

Ia / Ib / Ic
      ↓
Clarke
      ↓
Park ← ThetaE
      ↓
Id / Iq
      ↓
PI
      ↓
Ud / Uq
      ↓
Voltage Limit
      ↓
InvPark
      ↓
Ualpha / Ubeta
```

输出：

```text
Ualpha
Ubeta
```

# 18. Fast Control Tick

Fast Tick 由 ADC EOC 驱动。

概念执行顺序：

```text
ADC EOC
   ↓
Current Sample
   ↓
Encoder / State Process
   ↓
Position Loop
   ↓
Speed Loop
   ↓
Current Loop
   ↓
SVPWM
   ↓
PWM Update
```

第一阶段可以保持直接代码结构，不建立复杂 Scheduler。

例如：

```c
void Motor_FastLoop(void)
{
    Current_Sample();
    Encoder_Process();

    if (++Spd_Cnt >= SPD_DIV)
    {
        Spd_Cnt = 0;

        Speed_Calc();

        if (++Pos_Cnt >= POS_DIV)
        {
            Pos_Cnt = 0;
            Position_Loop();
        }

        Speed_Loop();
    }

    Current_Loop();
    SVPWM_Calc();
    PWM_Update();
}
```

实际实现可根据编码器 SPI 时序调整 `Encoder_Process()` 的位置，但控制调度思想保持简单。

# 26. 第一阶段一句话总结

> **第一阶段只实现能够让电机稳定运动的最短控制链：Servo 使用 `DISABLED / ENABLED / RUN` 三状态，使能与启动分离；Target 始终保留用户语义，只有 RUN 时执行；ADC 使用固定采样方案，不做动态两相选择；SPI 编码器直接提供位置和电角度，速度先用差分加简单滤波；Current / Speed / Position 三环由 ADC Fast Tick 分频执行；ThreadX 只承担 USB、命令和非实时任务。ESO、IPD、辨识、动态采样和完整产品级功能全部放到三环跑通之后。**
