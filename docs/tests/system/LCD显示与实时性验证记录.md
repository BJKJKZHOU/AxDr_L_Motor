# LCD 显示与实时性验证记录

日期：2026-10-11。

## 实装屏幕与显示方向

硬件来源为 `文档/开发板工程/ProDoc_1.axdr_v1.3_2026-10-02.epro2`。其中 `IPSLCD1` 标注 `TFT_1.14_135x240_13pin`；实装面板为 135×240，并且横向安装。原软件的 240×240、零偏移不适用。

最终配置：

| 项目 | 设置/验证 |
|---|---|
| 物理像素 | 135×240 |
| 逻辑坐标 | 横屏 240×135，X=0…239、Y=0…134 |
| 控制器/颜色 | ST7789、RGB565，高字节先传 |
| MADCTL | `0xA0`（MY、MV） |
| 显存偏移 | X=40、Y=52；窗口终点为 X=279、Y=186 |
| SPI3 | Mode 0、8 bit、170 MHz / 8 = 21.25 Mbit/s |
| 视觉确认 | 现场目视确认文字正向，TL/TR/BL/BR 四角及四边完整 |

135×240 面板在 240×320 控制器显存中的居中偏移随旋转方向变化，奇数宽度导致52/53 的区别。配置参考 [Adafruit ST7789 驱动的 init/setRotation](https://github.com/adafruit/Adafruit-ST7735-Library/blob/master/Adafruit_ST7789.cpp)，最终方向以本次实板反馈为准：`0x60` 横屏上下颠倒，改为 `0xA0` 后确认正常。

顶部信息压缩为两行、32 像素高：第一行模式/单位/状态，第二行 REF/FBK 及数值。下方 240×103（Y=32…134）全部显示五秒波形，删除底部 `-5S`、`NOW` 文字。2 bit 缓存每行 60 字节；240 像素宽度对应 15 个完整列块，传输块为 16×8，底部块裁切到 7 行。全屏恰好 64,800 字节，17 次矩形 DMA，避免漏掉第 135 行或写出屏幕边界。

## 背光黑屏原因

初次运行时 DMA 计数正常，但现场观察到屏幕和背光均黑。读取 GPIO 确认 PB7 为高电平；重新核对原理图发现 Q4 为 **S8550 PNP**，PB7 经过 R21 驱动基极，R22 将基极上拉到 VCC。因此 PB7 **低电平开背光，高电平关背光**，原代码和引脚文档写反。

通过 SWD 拉低 PB7 后，现场目视确认背光点亮、四角可见。已同步修正 `.ioc` 的 PB7 上拉/默认高、CubeMX 生成 GPIO，以及 ST7789 初始化：初始化期间保持高，清屏和 DISPON 完成后拉低。重启后自动点亮已实板确认。

## SPI 与 DMA 配置

SPI3 TX 使用 DMA2 Channel1、请求号 15，Memory→Peripheral、字节对齐、MemInc、Normal、Low priority；IRQ 优先级 8，PC10/PC12 为 Very High speed。LCD/外部 SPI3 片选默认高，PB7 上拉且默认高。应用池 3 KB，四个快环中断仍放在 CCMRAM。

板上确认 DMA 关联、时钟及 NVIC 配置，完成帧计数持续增加。

## 栈与内存

原 Panel 栈仅 512 B。本次先调整为 1024 B，但首次烧录停在`App_ThreadX_Init` 失败分支：2 KB 应用池容不下 Motor/Panel 两个 1024 B 栈、命令队列及分配开销。将 `.ioc` 的 `TX_APP_MEM_POOL_SIZE` 改为 `3*1024`，再经 CubeMX 生成后启动正常。

最终横屏、初始化、测试图和正反转刷新工况下：

- 分配的 Panel 栈：1024 B；ThreadX 控制块报告有效大小 1020 B。
- `tx_thread_stack_highest_ptr` 与栈底 `0xEF` 填充扫描均得到峰值 **640 B**，
  有效剩余 **380 B**。旧 512 B 容量不足。
- 原有 `TX_ENABLE_STACK_CHECKING` 保持开启。
- Clang Release（两行布局）：RAM 52,840 B / 96 KB，CCMSRAM 8,824 B / 32 KB，Flash 112,220 B / 496 KB。
- GCC Release（两行布局）：RAM 53,264 B，CCMSRAM 8,912 B，Flash 115,776 B。

栈峰值采用 Clang Release 固件实测。

## 刷新率和 FOC 运行态复测

旧横屏布局下，母线约 24.8 V，有感 SPEED ±200 RPM、Iq 限幅 1 A，速度环 50 Hz、ESO 100 Hz，加减速度 100 rad/s²。CPU/TIM1 170 MHz，PWM 20 kHz；每组稳定 1 s 后采集约 5 s，运行中不停核，耗时取整轮累计最大值。

| LCD 工况 | 完成更新率 | FOC 总耗时最大 μs |
|---|---|---:|
| 暂停刷新对照 | 0 | 42.176 |
| 正常局部刷新 | 正转 30.396、反转 30.193 FPS | 42.724 |
| 强制全刷对照 | 约 20.2 FPS | 42.318 |

正常刷新相比暂停时快环最大增加约 0.547 μs，距 50 μs 周期余量 7.276 μs。FPS 按最后一块 DMA 完成计数；局部刷新约 30.3 FPS、239～249 KB/s。全刷约 1.309 MB/s，完成延迟最大 50 ticks。暂停与强制全刷只用于当轮对照，后已删除。

## KEY3 四模式循环

KEY3/PC7 为上拉输入，通过面板扫描和命令队列切换 TORQUE → SPEED → POSITION → SENSORLESS_SPEED → TORQUE。OPEN_LOOP、IDENT、PHASE_SEARCH 按一次返回 TORQUE，未知模式保持；仅 DISABLED 接收切换，目标值保持。

测试使用 Clang Release 固件。通过 SWD 临时将 PC7 设为开漏输出，仅拉低模拟按下、释放为高阻，不驱动高电平；MCU 持续运行，通过真实按键扫描、消抖、队列和参数入口验证，并经 USB 读回模式/状态。

验证通过：

- 连续两轮四模式循环；每次按下、持续保持、释放分别读回，长按不连跳。
- OPEN_LOOP、IDENT、PHASE_SEARCH 分别按一次返回 TORQUE。
- ENABLED、RUN 时按下保持原模式；在 ENABLED 按住后取消使能，不补触发切换。
- 模式循环前后转矩、速度、位置目标完全保持。
- 从实际 `Key_Press` 提取的主机测试检查输入抖动、长按和释放后再次按下，
  ASan/UBSan 检查通过。

母线约 24.8 V，以 TORQUE、零转矩目标、1 A 参考限流进入 RUN，分别采样 3 s：

| 显示负载 | 完成帧数 | 刷新率 | 快环最大 | Panel 栈峰值 | Deadline / Enc Miss / Enc Late |
|---|---:|---:|---:|---:|---|
| 正常局部刷新 | 90 | 29.99 FPS | 39.959 μs | 640 B | 0 / 0 / 0 |
| 强制全屏刷新 | 58 | 19.33 FPS | 39.959 μs | 640 B | 0 / 0 / 0 |

DMA2 中断优先级 8，SPI3 TX 请求号 15；本轮运行态计时使用零转矩工况。

## 按键与显示状态精简回归（2026-10-18）

按键保持 5 tick 扫描、连续 3 次确认，以及 KEY1、KEY2、KEY3 的处理优先顺序；LCD 完成回调和等待统一使用 LCD_Online。

- 失能及零转矩运行分别连续检查约 3 s，LCD 画面时间持续更新、完整画面标志有效，
