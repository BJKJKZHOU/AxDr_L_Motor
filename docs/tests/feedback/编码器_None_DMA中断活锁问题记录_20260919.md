# 编码器 None 状态导致 DMA 中断活锁的问题与修复

日期：2026-09-19。

## 问题现象

上位机将 `Encoder Protocol` 从 `SPI` 切换为 `None` 后，设备不再响应后续AXDR 请求。GUI 等待写响应超时，并将界面中的协议值回滚为 `SPI`。

开发板并未进入 HardFault。CPU 因 DMA1 Channel 5 中断持续重入而无法继续执行线程，表现为功能性卡死。

## SWD 现场证据

三次独立 SWD 暂停采样均得到相同结果：

- CPU 位于 IRQ15：`DMA1_Channel5_IRQHandler()` → `Encoder_DMA_IRQHandler()`；
- `CFSR`、`HFSR`、`DFSR`、`AFSR` 均为 `0`，没有 Cortex-M Fault；
- `Drv_IRQHandler=0`，说明 `Encoder Protocol=None` 的参数变更已经执行；
- DMA1 Channel 5 仍处于工作状态：
  - `DMA1 ISR = 0x00570000`；
  - Channel 5 的 `GIF5`、`TCIF5`、`HTIF5` 未清除；
  - `CCR5 = 0x000025AB`；
  - `CNDTR5 = 1`；
- 被 IRQ15 打断的 Motor 线程正在执行
  `Protocol_Parameter_Write_Response()`。

`CCR5=0x25AB` 中 `EN`、`TCIE` 和 `TEIE` 仍然开启。虽然 `HTIF5` 也处于置位状态，但 `HTIE` 已关闭；维持中断请求的主要条件是 `TCIF5 + TCIE`。

## 原因分析

修改前，`Encoder_DMA_Config()` 对 `ENC_PROTOCOL_NONE` 的处理仅清空三个驱动函数指针：

```c
Drv_Config = 0;
Drv_Start = 0;
Drv_IRQHandler = 0;
return;
```

该路径没有完成旧 SPI 编码器驱动的硬件退出：

- SPI1 RX DMA 请求仍然开启；
- DMA1 Channel 5 仍然开启；
- DMA TC/HT/TE 中断源没有关闭；
- Channel 5 已置位的状态标志没有清除。

DMA1 Channel 5 中断入口直接调用编码器中断分发函数：

```c
void Encoder_DMA_IRQHandler(void)
{
    if (Drv_IRQHandler != 0)
    {
        Drv_IRQHandler();
    }
}
```

当函数指针为空时，该函数直接返回，没有清除 DMA 标志。异常返回后，DMA中断请求仍然有效，NVIC 随即再次进入 IRQ15。CPU 持续在同一中断中tail-chain，Motor 线程和 USB 协议处理无法获得执行时间。

完整因果链为：

```text
SPI → None
  → 清空编码器处理函数，但旧 SPI DMA 仍工作
  → DMA1 Channel 5 TC 标志持续请求 IRQ15
  → 空中断分发不清 DMA 标志
  → IRQ15 无限重入
  → Motor 线程无法完成 Parameter Write 响应
  → USB/AXDR 后续通信停滞
  → GUI 超时并回滚显示
```

## 修复要点

选择 None 时关闭 SPI1 RX DMA 请求、DMA1 Channel 5 和 TC/HT/TE 中断，清除全部标志并拉高片选。先清通道 EN，再修改中断使能位。

None_Start 不采样，None_IRQHandler 清除残留 DMA 标志。驱动切换先绑定 IRQ，再绑定 Start/Config，保证切换窗口中的残留中断能够清除标志。

## 修复后的状态语义

选择 `Encoder Protocol=None` 后：

| 状态 | 值 | 含义 |
|---|---:|---|
| `Encoder_Config.Protocol` | `ENC_PROTOCOL_NONE` | 对外明确显示没有编码器 |
| `Encoder.Ready` | `0` | 没有可用于控制的编码器反馈 |
| `Encoder.Valid` | `0` | 当前没有有效编码器样本 |
| `Encoder.Fault` | `0` | 未配置编码器，不属于编码器故障 |

`Feedback_Reset()` 仍负责清除原编码器反馈和速度历史。`None` 不会产生采样，也不会因缺少采样主动制造 Encoder Fault。

## 开发板实测

在 `DISABLED` 状态通过 `/dev/ttyACM0` 执行 `SPI → None`，Parameter Write成功返回。紧接着连续读取多个参数，结果为：

```text
Protocol_before = 1 (SPI)
Protocol_after  = 0 (None)
Encoder.Ready   = 0
Encoder.Valid   = 0
Encoder.Fault   = 0
Motor_State     = 0 (DISABLED)
```

写响应和后续读取均正常完成，未再出现 AXDR 超时。

随后通过 CMSIS-DAP 进行三次独立 SWD 暂停采样。三次 CPU 均处于正常的PendSV 调度中，没有停在 IRQ15：

```text
Sample 1: Handler PendSV, PC=0x08000274
Sample 2: Handler PendSV, PC=0x0800027C
Sample 3: Handler PendSV, PC=0x08000272
```

三次采样的外设状态一致：

```text
DMA1 ISR              = 0x00500000
DMA1 Channel 5 CCR    = 0x000025A0
DMA1 Channel 5 CNDTR  = 1
SPI1 CR2              = 0x00000F00
Drv_Start             = None_Start
Drv_IRQHandler        = None_IRQHandler
```

其中：

- `DMA1 ISR` 中 Channel 5 对应的四个标志位均为 0；
- `CCR5.EN/TCIE/HTIE/TEIE` 均为 0；
- `SPI1 CR2.RXDMAEN` 为 0；
- `CNDTR5=1` 是已停用通道中保留的旧计数值，不会触发传输或中断。

三次 SWD 暂停并恢复后，再次通过 CDC 读取参数仍然成功，状态继续保持`Protocol=None / Ready=0 / Valid=0 / Fault=0 / DISABLED`。

本次结果确认原 IRQ15 活锁已经消除，且 `None` 的对外状态符合设计。
